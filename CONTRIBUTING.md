# Contributing to FeeBumpStudio

Thanks for helping improve FeeBumpStudio.

## Before opening a change

1. Read the README and the relevant architecture notes.
2. Run the repository tests.
3. Keep changes focused.
4. Do not commit credentials, private keys, seed phrases, or production endpoints.
5. Explain protocol-facing changes clearly.

## Pull requests

Describe the problem, the change, tests performed, and any migration or deployment
impact. For contract changes, include the expected storage and authorization effects.
